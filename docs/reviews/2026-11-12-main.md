**Verdict**: Changes requested

## Summary
Adds Masaniello as a fourth money management style (spec 0004): a clean pure engine (`msTable`, `msPlanSummary`, live stake, advance, end check), persistence through both whitelists, a settings panel with validation and a plan summary, a start gate, Quick Log rows, and replay and correction support. Also folds in unrelated load work (batched screenshot signing, builtin strategy seeding run in parallel) and test updates for the multi strategy change. Spec 0003 is spec only; App.js holds no search or pair filter code yet. The math is right and well tested. The main problems: a cycle can run out of capital with no way to end, the engine is picked from the live setting instead of the session at several call sites, the 4 loss daily lock still applies to Masaniello in the Journal, and AC-18 (end at midnight) is missing.

## Major

### 🟠 A cycle that runs out of capital before the loss limit never ends and logs $0 stakes, `src/App.js:1605-1635`, `src/App.js:5618`
**Problem**: `msPlanStake` returns null when running capital is 0 or less, so `liveMasanielloNextStake` returns 0, but `checkMasanielloSessionEnd` only looks at win and loss counts. The $1 floor makes running capital run out before N minus K plus 1 losses. I simulated 6 of 10 at 92% with the cycle's own stake rule. At the advertised minimum capital ($3.24), stakes go $1, $1, $1, $0.24 and capital hits $0.00 after 4 losses, with the cycle still active (n=6, k=6). At $5 the same happens. In Quick Log, `draftStake = parseFloat(override) || liveStake` is then 0, so `commitRow` saves $0 trades. Six $0 "wins" drive `msWins` to K, the cycle ends `MS_TARGET`, and it counts as **Won** in today's events with $0 capital.
**Why it matters**: The Minimum capital the panel recommends can leave you in a stuck cycle that shows a fake win. A money tool should never show that.
**Suggested fix**: In `checkMasanielloSessionEnd`, end the cycle (`MS_LOSS_LIMIT`, or a new reason) when running capital is ≤ 0, or below the $1 broker minimum when the plan still needs a trade. Refuse a commit when the stake is ≤ 0 in `commitRow` and `addManual`. The test at `src/Masaniello.test.js:76-88` hides this: `toBeGreaterThanOrEqual(Math.min(1, rc))` passes when stake and capital are both 0, and the LLLL path stops before it reaches the stuck state. Add a test for LLLL then W at minimum capital. Also consider whether "first stake is $1" is the right minimum when every later stake has a $1 floor. That is a spec question for /architect.

### 🟠 Engine and end checks follow the live setting, not the session's snapshot, `src/App.js:1299-1301`, `1495-1497`, `1556-1557`, `5571`, `5600`, `5658`, `5696`, `4339-4341`, `3590`, `8841`
**Problem**: Spec AC-5 and the Settings warning ("Your current session continues under its original rules") promise a running cycle keeps its rules. `setOutcome`, `addManual` and the reconcile replay pick the engine from `sess.msN`, but these paths still use `getMoneyMgmtStyleForMode(settings)`:
- `checkAntiMartingaleSessionEnd` and `checkProfitLockSessionEnd` gate on the live setting. Switch Masaniello to Anti-Martingale mid cycle, and the Masaniello session gets AM's 60 minute cap and its % targets against `startBalance`, through the Dashboard tick (3590) and the App interval (8841).
- Quick Log's `style` (5571) feeds `liveEscalatingNextStake`, `advanceEscalatingStake` in `commitRow` and in `correctOutcome`. After a Masaniello to AM switch, Quick Log commits advance `amStreak` and never `msWins`/`msLosses`, so the cycle can never reach `MS_TARGET`/`MS_LOSS_LIMIT`.
- The reverse switch (an AM or PL session running, setting now Masaniello): `liveMasanielloNextStake(session)` gets a session with `msN == null` and returns **0**, so Quick Log, Journal `stakeFor`, and the Dashboard show and log $0 stakes. Separately, AM's own end checks stop firing for that session.
**Why it matters**: A settings change in the middle of a cycle silently corrupts the running cycle or logs $0 trades.
**Suggested fix**: Add one helper, e.g. `sessionMmStyle(sess, settings, mode)` = `sess?.msN != null ? 'MASANIELLO' : sess?.amNextStake != null ? 'ANTI_MARTINGALE' : sess?.plNextStake != null ? 'PROFIT_LOCK' : liveSetting`. Use it in every dispatcher call that has a session. Have the AM and PL end checks return null when `session.msN != null`. That fixes it in one place instead of at each call site.

### 🟠 The 4 losses per day lock still blocks Masaniello in the Journal (AC-11), `src/App.js:4420`, `src/App.js:4508`
**Problem**: `recordPA` and `addManual` call `isDailyCircuitBroken(trades, mode)` with no style exemption. The UI's `dailyLocked` uses `isModeDayLocked`, which does exempt escalating styles. A 6 of 10 cycle can legally take 4 losses and then must win 6 in a row, but the 4th loss of the day blocks every further Journal or Analyzer log. Losses from an earlier cycle that day count too.
**Why it matters**: AC-11 is not met. A cycle can't finish from the Journal, and the UI shows no lock while the save is refused with an alert.
**Suggested fix**: Use `isModeDayLocked(trades, ss, settings, mode)` (or a session aware equivalent) at both guards so the Journal matches the UI and Quick Log. The Analyzer's `locked` at 3819 has the same gap.

### 🟠 AC-18 (end a cycle at midnight as `MS_MANUAL`) is not built, `src/App.js:1042-1046`, `src/App.js:8569`
**Problem**: `MS_MANUAL` is set only in `endSession` (3500). No reconcile ends a cycle started before today. Only today's sessions are loaded, and `getToday` drops yesterday's `ss`. So a cycle left open across midnight disappears from the UI and stays `is_active = true` in the database with no `endReason`, forever. scope.md marks the "Integration (AC-14 to AC-19)" step done.
**Why it matters**: The spec contract and its critical test scenario are unmet, and the scope doc says otherwise. Open cycles are abandoned with no record.
**Suggested fix**: On load (and on day rollover), find active Masaniello sessions whose `startTime` date is before `tod()` and write `isActive:false, endReason:'MS_MANUAL'`. That needs one query for active sessions with `date < today`. Or untick the scope step and revise the AC.

### 🟠 New branching logic outside the pure engine is untested, `src/App.js:1669`, `1678`, `4361`, `5636`, `8764-8802`
**Problem**: `src/Masaniello.test.js` covers the math well, but nothing tests the start gate (`msStartBlockReason`, `mkSession` returning `false` so the trade is dropped, AC-17), the pending block (`msHasPendingTrade`, AC-15), replay and correction recounts (AC-19), `MS_LOSS_LIMIT` counting toward the 2 session lock (AC-11), `buildSession` snapshot plus whitelist round trip (AC-5, AC-12), or `MS_MANUAL` on manual end. These are the paths where the bugs above sit.
**Why it matters**: Test signal is configured. This is branching, money relevant logic.
**Suggested fix**: Hand to /test: unit tests for `msStartBlockReason`, `amPlLossTargetSessionCount` with `MS_LOSS_LIMIT`, and `toSessionRow`/`fromSessionRow` round trip of the ms keys. Add one RTL test that Quick Log on a Masaniello session refuses a second log while a trade is pending.

## Minor

### 🟡 Quick Log ignores the 2 loss target sessions daily lock, `src/App.js:5744`, `src/App.js:5676`
**Problem**: Quick Log's Start session and `commitRow` never check `isAmPlDailyLocked`. After two `MS_LOSS_LIMIT` cycles, Quick Log still starts a third. AM and PL already had this gap, but AC-11's Masaniello lock now depends on it.
**Suggested fix**: Disable Start (and block `startSession` in `useSessionControls`) when `isAmPlDailyLocked(ss, mode)`, with the same message the Dashboard shows.

### 🟡 Analyzer logging applies Trade Management stop rules to a Masaniello cycle, `src/App.js:4431-4445`
**Problem**: `recordPA` runs `chkLock(sess, styleId)` on any session. `addManual` skips it for escalating sessions. A Masaniello cycle can take several losses by design, so under Strict that blocks Analyzer logs, and under Soft it marks them off plan. AM and PL had this before, but it hits Masaniello harder.
**Suggested fix**: Skip `chkLock` when the session's style is escalating, as `addManual` does.

### 🟡 Stake drops below $1 when running capital is under $1, with no explanation, `src/App.js:1613-1616`
**Problem**: `Math.min(rc, Math.max(1, plan))` returns e.g. $0.24 or $0.46 (seen in the simulation, including all in k = n trades at $10 capital). AC-6 says "never below $1". The reasoning line names the $1 raise only when stake > plan, so it is silent here. The broker will reject the trade.
**Suggested fix**: Settle this together with the first Major: end the cycle, or say clearly that the stake is below the broker minimum.

### 🟡 `signShots` failure is not handled, `src/App.js:420-430`, `src/App.js:8607`
**Problem**: If `createSignedUrls` rejects (network), the async load function throws after `setLoading(false)`. That is an unhandled rejection, and every screenshot keeps its raw storage path (broken images) with no log. The returned `error` is logged, but a thrown error is not.
**Suggested fix**: Wrap the sign step in try/catch and log, so the app keeps working without signed URLs.

## Nits
- ⚪ `src/App.js:5769`: Losses metric colours look inverted: red when far from the limit, amber when one loss away.
- ⚪ `src/App.js:7622-7636`: `msCleaned` validates K against the typed N even when N is in error and keeps its old value, so the stored K can exceed stored N minus 1. The getter clamps it, but the saved pair is inconsistent.
- ⚪ `src/App.js:1641-1646` / `src/App.js:8786`: `msCountsFromTrades` is not capped at the bounds, while `advanceMasaniello` (used by `correctOutcome`) is, so the two recount paths can disagree on an over-bound ended session.
- ⚪ `src/setupTests.js:8`: a global 5 s `asyncUtilTimeout` hides slow renders for every test. Prefer per test timeouts where the full App mounts.
- ⚪ `src/App.js:1516`: `isEscalatingStyle` now means "has its own session rules" (the spec notes this), and three call sites need `&&style!=='MASANIELLO'`. A second predicate (`isStakeEscalatingStyle`) would read better.

## Strengths
- The pure engine is small, correct, and matches the spec's recurrence. The wins first and losses first tests prove path independence to within a cent, and the drift test checks self correction.
- Persistence is handled carefully: ms keys go into both the settings and session whitelists with `??null`, so nothing silently disappears on reload.
- The `mkSession` `false`/`null` distinction makes the auto start gate drop the trade instead of saving it unlinked, as AC-17 asks.
- Batched `createSignedUrls` plus functional `setTrades` after first paint is a real load fix, and it doesn't lose trades logged in the meantime.

## Test coverage
`src/Masaniello.test.js` covers the math (Cf ratio, path independence, loss limit, draw push, k = n all in, drift, minimum capital, $1 raise, settings validation including Stop Loss %). The App.test.js changes only bring older tests in line with `strategyIds` and isolate storage. Untested: start gate and `mkSession` refusal, pending block, replay and correction recounts, the daily lock with `MS_LOSS_LIMIT`, session snapshot round trip, manual end reason, Quick Log Masaniello UI. The minimum capital "full cycle" test asserts too loosely and misses the stuck at $0 state (see first Major).
